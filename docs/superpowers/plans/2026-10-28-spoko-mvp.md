# spoko MVP — plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Klient (CLI + daemon + tray) i serwer w Ruście, które natychmiast synchronizują stan pracy developera (pliki, stan gita, `.env`, czaty Claude Code, Docker volumes) między jego komputerami, z szyfrowaniem E2E i mergem opartym na gicie.

**Architecture:** Klient trzyma per projekt wewnętrzne bare repo git (libgit2) jako magazyn snapshotów; snapshot = commit z drzewem `work/ gitstate/ external/ meta/`. Obiekty są szyfrowane per obiekt (XChaCha20-Poly1305), identyfikowane keyed-BLAKE3 i wysyłane do serwera, który jest głupim magazynem blobów + wskaźniki z compare-and-swap + WebSocket z powiadomieniami. Merge (3-way, libgit2) wyłącznie po stronie klienta. Klient jest synchroniczny (wątki + kanały, bez tokio), serwer asynchroniczny (axum).

**Tech Stack:** Rust stable (1.95), `git2` (vendored libgit2, bez https/ssh), `ignore`, `notify` (8.x stable), `fastcdc`, `chacha20poly1305`, `crypto_box` (0.9, feature `seal`), `blake3`, `ureq` + `tungstenite` (rustls), `interprocess`, `fd-lock`, `crossbeam-channel`, `unicode-normalization`, `serde`/`serde_json`/`toml`/`bincode`, `clap`, `notify-rust`, `bollard` (+ lokalny `tokio` current-thread tylko w module docker), serwer: `axum`, `tokio`, `rusqlite` (bundled). Tray: `tray-icon` + `tao`. Testy: `cargo test`, `tempfile`, `cargo llvm-cov`.

**Spec:** `docs/superpowers/specs/2026-10-28-spoko-design.md`

## Global Constraints

- Jeden workspace Cargo; binarki: `spoko` (CLI+daemon), `spoko-server`, `spoko-tray`.
- Systemy: macOS, Linux, Windows. Kod `cfg(windows)` musi się kompilować: `cargo check --workspace --exclude spoko-tray --target x86_64-pc-windows-gnu`.
- spoko **nigdy** nie dodaje do `.git` użytkownika niczego swojego (refy, klucze config, pliki); zapisuje tam tylko dane użytkownika z innego urządzenia, wyłącznie przez libgit2.
- spoko **nigdy** nie pushuje do zdalnych repo gita i nie potrzebuje poświadczeń gita.
- Każdy zapis pliku: temp `.spoko-tmp-<losowe>` w tym samym katalogu + rename; poprzedni stan zawsze jest w snapshocie przed nadpisaniem.
- Wewnętrzne repo bez `autocrlf`, bez filtrów; bajty plików 1:1.
- Katalog stanu klienta: `$SPOKO_HOME` lub `~/.spoko`. Każdy test używa `SPOKO_HOME` w `tempfile::TempDir`; testy nie dotykają prawdziwego `~`.
- Serwer nie dostaje nigdy plaintextu: nazw plików, treści, nazw projektów, nazw volumenów, oidów gita.
- Cele wydajności (spec §16): mała zmiana → druga maszyna < 1 s p50 / < 3 s p95 (lokalny serwer); idle ~0% CPU, < 50 MB RAM; 100 000 plików bez degradacji; zimny skan < 2 s; pierwsza synchronizacja przyrostowa i wznawialna.
- Konwencja testowalności: błędy I/O i sieci wstrzykiwane przez małe traity/fault-hooki (`ApplyFaults`, `ObjectServer`, `DockerApi`, `Notifier`), nie przez `coverage(off)`.
- Pokrycie testami: 100% linii w crate'ach `spoko-crypto`, `spoko-proto`, `spoko-core`, `spoko-client`, `spoko-server` mierzone `scripts/coverage.sh`. Jedyne wyłączenia (lista w skrypcie, każde z komentarzem): pliki `*/os_glue/*.rs` — wywołania OS nie do uruchomienia w teście (launchctl/systemctl/rejestr, natywne powiadomienia, pętla zdarzeń traya), `spoko-docker/src/bollard_api.rs` gdy brak Dockera (pokrywany przez testy z `SPOKO_DOCKER_TESTS=1`), kod `cfg(windows)`/`cfg(target_os = "linux")` na hostach, gdzie się nie kompiluje (pokrywany w CI na danym systemie).
- Binarne/duże: wzorce z configu, `filter=lfs`, heurystyka NUL w pierwszych 8000 bajtach, próg `10MB` (domyślny `size_threshold`).
- Szybkość [prośba autora: „turbo szybkie, optymalizacja na maksa”]: każdy obiekt kompresowany **zstd** (poziom 3, przed szyfrowaniem); jeśli wynik ≥ 95% surowego — zapis surowy (flaga w nagłówku plaintextu), żeby nie marnować CPU na już skompresowanych (jpg, zip, mp4). Volumeny: zstd poziom 1 strumieniowo. Upload i download równolegle, 4 batche naraz, jeden `ureq::Agent` z keep-alive; powiadomienia tylko przez stałe WebSocket (bez pollingu). Profil `release`: `lto = "fat"`, `codegen-units = 1`, `opt-level = 3`, `panic = "abort"`, `strip = true`.
- Chunking: blob > 1 MiB dzielony FastCDC (min 256 KiB, avg 1 MiB, max 4 MiB). Max rozmiar pojedynczego obiektu na serwerze: 8 MiB.
- Domyślne zawsze-ignorowane: `.DS_Store`, `Thumbs.db`, `.idea/workspace.xml`, `.spoko-tmp-*`, pliki tymczasowe edytorów `*.swp`, `*.swx`, `4913`, `*~`, `*___jb_tmp___`, `*___jb_old___`, oraz `.git` (obsługiwany osobno przez gitstate).
- Ochrona masowego usuwania: brak katalogu projektu albo snapshot usuwa > 30% śledzonych plików **i** > 50 plików → pauza projektu + powiadomienie; `spoko resume --confirm` wypycha.

## Review Focus

1. **Zapis „atomic save” edytora** (vim `4913`/`.swp`/`~`, JetBrains `___jb_tmp___`, VS Code rename) — oczekiwane: snapshot zawiera tylko plik końcowy, bez śmieci i bez fałszywego „usunięcia” w trakcie. Test: Task 11 `incremental_tmp_then_rename_yields_final_file_only`.
2. **Operacja gita w trakcie zastosowania zmian z sieci** (`index.lock` istnieje, user robi `git checkout`) — oczekiwane: gitstate czeka, pliki robocze nie są pisane w połowie checkoutu użytkownika. Test: Task 14 `apply_defers_while_index_lock_present`.
3. **Ogromny plik wrzucony do projektu** (np. 2 GB wideo) — oczekiwane: strumieniowanie, brak ładowania całości do RAM, transfer w chunkach. Test: Task 10 `write_blob_streams_large_file` + Task 19 `large_blob_roundtrip_chunked`.
4. **Crash daemona w trakcie apply** — oczekiwane: `base` nie przesuwa się przed końcem apply, sieroty `.spoko-tmp-*` sprzątane przy starcie, kolejna synchronizacja zbiega się. Test: Task 21 `crash_mid_apply_converges`.
5. **Odmontowany dysk / skasowany katalog projektu** — oczekiwane: brak propagacji masowego usunięcia. Test: Task 21 `mass_delete_pauses_project` i `missing_root_pauses_project`.

**Files:**
- Create: `crates/spoko-crypto/src/{keyring,aead,ids,sealed,recovery,keyfile}.rs`
- Test: moduły `#[cfg(test)]` w tych plikach

**Interfaces:**
- Produces:
  - `pub struct Keyring { pub keys: BTreeMap<u32, Key32>, pub id_key: Key32 }`; `Keyring::generate() -> Keyring` (wersja 1); `current(&self) -> (u32, &Key32)`; `rotate(&mut self) -> u32` (dodaje nową wersję, `id_key` bez zmian); `to_bytes/from_bytes` (serde+bincode).
  - `pub fn seal(kr: &Keyring, aad: &[u8], plaintext: &[u8]) -> Vec<u8>` — format `[u32 LE wersja][24 B nonce][ciphertext+tag]`; `pub fn open(kr: &Keyring, aad: &[u8], sealed: &[u8]) -> Result<Vec<u8>, CryptoError>`.
  - `pub struct ObjectId(pub [u8; 32])` (hex Display/FromStr, serde jako hex); `pub fn git_object_id(kr, oid: &[u8]) -> ObjectId` = `blake3::keyed_hash(id_key, b"git\0" ++ oid)`; `pub fn chunk_id(kr, chunk: &[u8]) -> ObjectId` = keyed_hash(`b"chunk\0" ++ blake3(chunk)`); `pub fn name_id(kr, kind: &str, name: &str) -> String` (hex, do nazw wskaźników/volumenów).
  - `pub struct DeviceKeypair { secret: crypto_box::SecretKey }`; `generate()`, `public() -> [u8;32]`; `pub fn seal_to(pubkey: &[u8;32], data: &[u8]) -> Vec<u8>` (sealed box); `DeviceKeypair::unseal(&self, sealed) -> Result<Vec<u8>>`.
  - `pub fn fingerprint(pubkey: &[u8;32]) -> String` — `blake3(pubkey)` pierwsze 6 bajtów jako `xxxx-xxxx-xxxx` hex.
  - `pub struct RecoveryKey([u8;32])`: `generate()`, `to_display() -> String` (base32 bez paddingu, grupy po 4 znaki z `-`), `parse(&str)` (ignoruje wielkość liter, spacje, `-`); `wrap(&self, keyring_bytes) -> Vec<u8>` / `unwrap(...)` (XChaCha z kluczem = RK, AAD `b"spoko-recovery"`).
  - `pub fn write_private_file(path, bytes) -> io::Result<()>` (Unix: tworzy z trybem 0600; Windows: `cfg(windows)` ACL tylko bieżący użytkownik przez `windows-acl`/`icacls` — w `os_glue`); `read_private_file`.
